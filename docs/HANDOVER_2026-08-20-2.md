## 0. 🔴 이 세션에서 가장 중요한 것 — 내가 낸 사고

**가드레일을 조였다가 운영을 멈춰 세웠다.** 순서가 이랬다.

```
1. 루틴 고도화 1단계 구현 · 로컬에서 실제 AI로 태워 봄
2. 실측이 버그를 잡음 — 체형 목표에 건강 문제 코드가 붙는다
3. "어긋나면 재생성"으로 고침 · 다시 태워서 통과 확인 · 배포
4. 🔴 운영에서 500 — 모델이 두 번 다 같은 답을 내면 가드레일이 포기한다
5. 재생성이 아니라 **보정**으로 바꿔 다시 배포
```

3번에서 **실패 경로를 생각하지 않았다.** 로컬에서 한 번 통과한 것만 보고 배포했는데,
가드레일은 *"고칠 때까지 다시 시킨다"*가 아니라 *"두 번 해보고 안 되면 포기한다"*였다.

> **AI 응답을 검증할 때는 "안 고쳐지면 어떻게 되는가"를 먼저 정한다.**
> 사용자가 빈손으로 돌아가야 할 만큼 심각한 문제인가? 아니면 다듬고 넘어갈 것인가?

`RoutineService.normalize`가 지금 그 답이다 — **던지지 않는다.**

| 어긋난 것 | 어떻게 |
| --- | --- |
| 문제 코드가 카테고리와 안 맞음 | **코드만 지우고 태스크는 살린다** |
| 근거가 빈 문자열 | null로 둔다. 지어 채우지 않는다 |
| CORE가 하나도 없음 | 첫 태스크를 CORE로 올린다 |

**라벨이 어긋난 것과 내용이 잘못된 것은 다르다.** 지어내기를 막는 힘은 스키마의
`enum`에서 나온다 — 목록 밖은 애초에 고를 수 없다. 카테고리가 어긋난 것은 *분류가
애매한 것*이지 없는 것을 만들어 낸 것이 아니다. 스트레칭을 체형에 둘지 건강에 둘지는
사람도 갈린다.

테스트 `RoutineNormalizeTest`가 **어떤 입력이 와도 던지지 않는 것**을 못박는다.

## 1. 루틴 고도화 1단계 (`3a29e57` · `2905b77` · `996bdab`)

사용자 요청 — *"없는 단어나 말을 지어서 하지 말고, 필수 루틴이랑 선택 루틴으로
나눠서 생성해줘. 루틴을 생성할 때 좀 구체적으로 작성을 해줘."*

계획은 [ROUTINE_UPGRADE_PLAN.md](ROUTINE_UPGRADE_PLAN.md)에 있다. 1단계만 했다.

### 1-1. 지어내지 않기 — 프롬프트가 아니라 구조로

🔴 **프롬프트로는 못 막는다.** 지금 프롬프트는 170줄이고 `timing`과
`frequencyPerWeek`를 일치시키라고 못 박아 두었는데도 어긋난 적이 있다(08-19 §2).

| 겹 | 막는 것 |
| --- | --- |
| `ProblemCode` enum → JSON Schema `enum` | **없는 문제를 만들어 내는 것** |
| `normalize`의 카테고리 대조 | 엉뚱한 분류로 저장되는 것 |
| 빈 근거 → null | 근거를 요구해 놓고 빈칸을 받는 것 |

**문제 코드 목록은 enum에서 만들어 스키마에 끼운다**(`JsonSchemas.withProblemCodes`).
손으로 적어 두면 코드를 더할 때 한쪽만 고쳐 조용히 어긋난다.

### 1-2. 필수 · 보조 · 선택

`CORE` / `SUPPORT` / `OPTIONAL`.

🔴 **`OPTIONAL`은 날짜로 펼치지 않는다.** V15가 태스크를 기간 안의 모든 날로 펼치므로
(52주면 태스크 하나가 364행), 선택 항목까지 펼치면 목표 하나가 4천 행을 넘긴다.
시작일에 **한 행만** 두고 "해보면 좋은 것" 목록으로 보여준다.

```
5개 전부 펼침  1,820행  →  선택 2개 제외  1,092행
```

화면 규칙 — 오늘 할 일·캘린더에서 `OPTIONAL`을 뺀다(`scheduledTasks`).
`SUPPORT`에는 `보조` 배지가 붙고, `CORE`에는 붙이지 않는다(대부분이 필수라 온통
배지가 된다).

> **정렬은 시점이 먼저다.** 화면이 아침 → 저녁 → 자기 전으로 먼저 묶으므로,
> 아침 보조가 자기 전 필수보다 위에 온다. 중요도는 **묶음 안에서만** 앞선다 —
> 하루 흐름을 깨지 않는 편이 맞다고 보고 그대로 뒀다.

### 1-3. 구체적으로 — `reason` · `expectedEffect`

프롬프트에 *"reason은 **이 사용자의 입력을 가리켜야 한다**"*를 못 박았다.

```
좋은 예)  "평균 수면 시간이 5.5시간으로 짧게 제시되어 있어, 먼저 잠드는 시간을
          일정하게 만드는 쪽이 필요합니다."
나쁜 예)  "피부 건강에 도움이 됩니다."   ← 누구에게나 하는 말이다
```

실측에서 앞의 형태로 나왔다. 태스크 상한은 4~6 → **6~10**으로 올렸다.

### 1-4. V16에서 지킨 것

| 컬럼 | | 왜 |
| --- | --- | --- |
| `importance` | `NOT NULL DEFAULT 'CORE'` | 옛 태스크가 "필수만 보기"에서 사라지면 안 된다 |
| `problem_code`·`reason` | **nullable** | 옛 태스크에는 근거가 없다 — **없는 것을 지어 채우면 목적을 스스로 어긴다** |

화면은 `reason`이 없으면 **그 줄을 그리지 않는다.** "정보 없음" 같은 문구도 안 넣는다.

## 2. 프론트 — 깨지던 기호와 큰 사진 (`7ecd3c9`)

### 2-1. 폰트에 없는 글자는 네모가 된다

이 앱은 모든 텍스트에 Pretendard를 지정한다. 그 폰트에 없는 글리프는 기기마다 다른
대체 폰트로 떨어지고, **안드로이드에서는 네모(두부)로 뜨기도 한다.** 특히
`⌄`(U+2304)와 `⚙`(U+2699)이 빠져 있는 폰트가 흔하다.

[components/ui/Icon.tsx](../frontend/src/components/ui/Icon.tsx)로 옮겼다 —
check · close · gear · chevron · caret. SVG라 어디서나 같게 보이고, 획 굵기를 크기에
비례시켜 작게 써도 뭉개지지 않는다.

### 2-2. 웹은 원본을 그대로 올린다

운영 로그에서 `FILE_TOO_LARGE`가 잡혔다. 네이티브는 picker가 `quality`로 다시
인코딩해 주지만 **웹은 고른 파일을 원본 그대로 올린다.** 요즘 폰 사진은 10MB를
쉽게 넘는다.

올리기 전에 캔버스로 긴 변을 2048px까지 줄이고 JPEG로 다시 굽는다. 서버가 얼굴을
볼 때 1600px로 낮추므로 인식에도 충분하다. **줄이다 실패하면 원본을 그대로 보낸다.**

> `IMAGE_NO_FACE`는 별건이다. OpenCV **Haar 정면 검출기**(2001년 방식)라 고개를
> 살짝 돌리거나 앞머리·안경에 가리면 못 찾는다. 사람 눈에 멀쩡해도 걸린다.
> 고치려면 검출기를 바꿔야 한다 — 손대지 않았다.

## 4. 로그인 유지 시간 — 실측

사용자 질문에 답하려고 로컬에서 토큰을 열어 봤다.

| | 유효기간 |
| --- | --- |
| 액세스 토큰 | **30분** |
| 리프레시 토큰 | **14일** |

두 토큰 모두 `@go/session-v1`에 저장된다(웹은 localStorage, 앱은 네이티브 저장소).
앱을 껐다 켜면 `restoreSession`이 읽고, 액세스가 만료됐으면 첫 API 호출이 401 →
`tryRefresh` → 재시도로 이어진다. **사용자는 401을 보지도 못한다.**

**갱신할 때마다 리프레시도 14일로 다시 채워진다.** 즉 14일에 한 번씩만 열면 무기한
유지된다.

> 🔴 **리프레시 토큰을 회수하지 않는다.** 옛 리프레시로 다시 갱신해도 200이 나온다 —
> 상태 없는 순수 JWT라 서버가 "이미 쓴 토큰"을 기억하지 못한다. 로그아웃해도 그
> 토큰은 서버에서 계속 유효하다(기기에서 지울 뿐이다). 조이려면 리프레시 토큰을
> DB에 저장해야 한다.

값을 바꾸려면 `application.yml`의 두 줄이고 **백엔드만 재배포**하면 된다
(APK 재빌드 불필요).

## 5. 남은 것

### 🔴 FCM — 알림을 실제로 보내려면

백엔드 발송기도 프론트 토큰 등록도 다 되어 있다. 막고 있는 것은 FCM 자격 하나다.
콘솔 작업 ~15분 + 재빌드 ~20분, 비용 0원. [PUSH_FCM.md](PUSH_FCM.md)에 절차가 있다.

### APK 재빌드 — 오늘 프론트 변경이 전부 담긴다

자르기 테마 · 아이콘 벡터화 · Google 한 번 누르기 · 루틴 필수/선택 화면 · 사진 축소.
**키스토어를 다시 만들지 않는다** — SHA-1이 바뀌면 Google 로그인이 조용히 깨진다.

### 루틴 고도화 2·3단계

계획 §5·§6. 2단계는 `GapItem`으로 분석 결과와 루틴을 잇는 것이고, 3단계는 기간별
단계(phase)·성분 가이드·조정 규칙이다. **1단계 없이 2단계를 먼저 하면 안 된다** —
`GapItem`을 만들어도 태스크에 `problemCode`가 없으면 이을 곳이 없다.

### 확인하면 좋은 것

- **Google 로그인 실제 성공** — 400은 고쳤지만 진짜 계정으로는 못 눌러 봤다
- **안드로이드 SHA-1** — 재발급이 아니라 현재 EAS 키스토어 지문과 콘솔 값이 같은지 확인
- **S3 업로드(PutObject)** — 삭제는 확인했지만 업로드는 안 태워 봤다

## 6. 알아두면 시간 아끼는 것

- 🔴 **가드레일을 조일 때는 실패 경로를 먼저 정한다.** 재생성은 두 번이 끝이고,
  그래도 안 되면 **사용자가 빈손으로 돌아간다.** 다듬고 넘어갈 수 있는 것이면
  던지지 말고 다듬는다.

- **AI를 부르는 경로는 실제로 한 번 태워 본다.** 백엔드 174건·프론트 102건이 다
  통과했는데도 카테고리 어긋남은 살아 있었다. 몇 초·수 원이면 끝난다.

  ```bash
  cd backend && set -a && . ./.env && set +a && SPRING_PROFILES_ACTIVE=local ./gradlew bootRun
  ```

  프로필이 있어야 루틴을 만들 수 있는데, **사진 검증은 루틴과 무관하므로** 로컬
  DB에 프로필 행을 직접 넣는 편이 빠르다.

- **psql on Windows는 클라이언트 인코딩을 맞춰야 한다.** 쿼리에 한글이 있으면
  `PGCLIENTENCODING=UTF8`을 주거나, 아예 한글 리터럴을 쓰지 않는다.

- **PowerShell에서 `curl`로 한글 JSON을 보내면 깨진다.** 파일로 쓰고
  `--data-binary @file`을 쓰거나, 파이썬 `urllib`로 보낸다.

- **`git add backend`는 저장소 루트에서만 된다.** `cd backend` 뒤에 하면
  `pathspec did not match`가 난다. 앞선 명령의 `cd`가 남아 있는지 본다.

- **배포 순서는 정지 → 교체 → 시작이다.** 실행 중에 jar를 바꾸면 옛 프로세스가
  종료 훅에서 `NoClassDefFoundError`를 뱉는다(무해하지만 로그가 지저분하다).

- **SSH만 막히고 웹은 멀쩡하면 거의 항상 공인 IP다.** 보안그룹이 22번을 내 IP만
  허용한다. 오늘만 두 번 겪었다.

  ```powershell
  (Invoke-RestMethod https://api.ipify.org?format=json).ip
  Test-NetConnection 1.201.117.65 -Port 22 -InformationLevel Quiet
  ```
