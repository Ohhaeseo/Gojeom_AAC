## 2. 완료한 것

### 법적 필수 — 만 14세 미만 차단 (`2aa376d`)

개인정보보호법상 만 14세 미만은 법정대리인 동의가 필요한데 **나이를 물어보는 곳이
없어 준수 여부를 판단할 근거 자체가 없었다.** 가입 화면에는 "사용자 동의에 따라
관리합니다"라고 적혀 있었지만 동의를 받는 곳도 없었다.

- **생년월일을 `users`에 뒀다.** `profiles.birth_date`로 받을 계획이었으나 그 자리로는
  늦다 — 프로필은 사진·우선순위·신체 정보까지 받은 뒤에야 만들어지는데, 나이 확인은
  **어떤 개인정보든 수집하기 전에** 끝나야 한다. 같은 사실을 두 곳에 두지 않으려고
  `profiles.birth_date`는 없앴다(V10 아님, **V9**).
- 동의는 네 항목으로 나눈다. 묶어서 받으면 선택 항목이 사실상 필수가 되어 법이
  금지하는 형태가 된다. 얼굴 사진과 건강 정보는 **민감정보**라 `BIOMETRIC`으로 따로.
- **거부한 항목도 행을 남긴다.** "물어봤는데 거부"와 "아직 안 물어봄"은 다르다.
- **Google 최초 로그인도 회원가입이다.** 그냥 두면 동의 없이 계정이 생기므로 같은
  검사를 건다. 값이 없으면 `CONSENT_REQUIRED`로 돌려보내고 가입 화면에서 받아 다시 부른다.

| 실측 | 결과 |
| --- | --- |
| 만 13세 | **403** `PROFILE_UNDERAGE` |
| **만 14세 생일 당일** | **201 통과** ← 법이 막는 것은 *미만*이다 |
| 민감정보 동의 누락 | **403** `CONSENT_REQUIRED` |
| 생년월일 없음 | **400** `VALIDATION_ERROR` |

> 에러 코드는 **이미 있던** `PROFILE_UNDERAGE`·`CONSENT_REQUIRED`를 쓴다. API.md가
> 문서화해 두었는데 쓰는 코드가 없던 것이라 새로 만들지 않았다.

### 목표 기능 (`ed22a7b` · `b90bb7c` · `2e2a109`)

- **삭제·이름 변경** — 삭제 API는 있었고 화면만 없었다. 이름 변경은 `PATCH /routines/{id}` 신설.
- **순서 변경** — `PATCH /routines/order`가 **전체 순서를 통째로** 받는다. 상대 지시
  ("3번을 위로")는 중간에 목표가 지워지면 어긋난다.
- **카테고리별 목표 입력** — `/routine-new`(카테고리·기간) → `/routine-goal`이
  **카테고리마다 한 장씩**. 체형은 목표 몸무게 + 문장, 피부·건강은 문장.
- **카테고리로 묶어 표시.** 진단 기반 목표는 카테고리가 없어 맨 뒤에 따로 모은다.
- `이번 주 할 일` → **`오늘 할 일`**, 소요 시간 표시 제거, 시점 순 정렬.

### 화면 (`964d959`)

- 진행률 `86%` 하드코딩 제거 → **서버가 주는 실제 값**. 서버가 안 주는 화면은
  숫자를 지어내지 않고 흐르는 막대만 보여준다.
- **홈에서 오늘 할 일 체크.** 고르고 정렬하는 규칙은 `lib/tasks.ts`로 빼서 홈과 루틴

- 분석 결과에서 **사용자가 고른 키워드**를 본문에 강조.

## 3. 오답 노트 추가분

AGENTS.md §4-1로 옮길 것.

### N-13. 라이브러리가 웹에서 조용히 죽는다

`react-native-draggable-flatlist`를 넣었더니 **끌어도 아무 일이 없었다.** 셀 위치를
`findNodeHandle`로 재는데 **RN Web에 그 API가 없다.** 콘솔에 경고 한 줄만 남기고
에러도 던지지 않아, 화면만 보면 "왜 안 되지"에서 멈춘다.

**재발 방지** — 네이티브 라이브러리를 웹에 쓸 때는 **실제로 그 동작을 해 보고**
확인한다. 렌더링이 된다고 동작하는 것이 아니다. 지금은 `PanResponder`(코어)로
직접 만들어 웹·앱을 한 벌로 덮는다. (`DragList`)

> **끌기와 버튼을 둘 다 준다.** 끌기는 입력기기에 따라 안 잡힐 수 있어, 순서를
> 바꾸는 길이 최소 하나는 늘 열려 있어야 한다.

### N-14. 애너테이션과 선언 사이에 끼워 넣지 않는다

`RoutineRenameRequest`를 `RoutineSummary` 바로 위에 넣으면서 `@JsonInclude(ALWAYS)`를
떼어놨다. 애너테이션이 새 레코드에 붙어 **경로 A 응답에서 `category: null` 키가
사라졌다.** 기존 회귀 테스트가 잡아줬다.

**재발 방지** — 레코드·클래스 위에 무언가를 추가할 때는 **바로 위 줄이 애너테이션인지**
본다.

### N-15. 마이그레이션을 쓰기 전에 기존 것을 전부 읽는다

V9에 `CREATE UNIQUE INDEX ux_consents_user_code`를 넣었는데 **V1이 이미 만들고 있었다.**
V1의 앞부분만 보고 인덱스 선언이 뒤에 있는 것을 놓쳤다.

**재발 방지** — 같은 이름이 있는지 `grep`으로 먼저 확인한다. Postgres가 DDL을
트랜잭션으로 되돌려서 실패 기록조차 남지 않아 repair 없이 복구됐다.

## 5. 확인하지 못한 것

**로그인이 필요한 화면은 눈으로 확인하지 못한 것이 있다.** 비밀번호 입력을 대신 하지
않아서, API로 계정을 만들고 세션을 브라우저에 넣어 확인했다. 그 방법으로 확인한 것:

- 목표 카테고리 묶음 · 순서 변경(▲▼) · 홈의 오늘 할 일 체크 · 홈 배치

확인하지 못한 것:

- **끌어서 순서 바꾸기가 실제 손가락·마우스로 되는지.** 합성 이벤트로는 RN Web의
  반응 시스템이 잡히지 않는다. ▲▼ 버튼은 실측으로 동작을 확인했다.
- **실제 Google 계정 로그인.** 계정 생성이 따르는 작업이라 사용자가 직접 눌러야 한다.
- **AI가 만든 실제 루틴에서의 시점 정렬.** 테스트 데이터가 영어라 판정이 안 됐고,
  한글 시점으로 로직만 따로 검증했다(아침 → 점심 → 모름 → 저녁 → 자기 전).

## 6. 알아두면 시간 아끼는 것

- **한글을 셸로 파이프하지 않는다** (N-5). curl 본문의 한글 닉네임이 깨져 400이 났다.
  psql뿐 아니라 **curl도 마찬가지다.** 점검용 데이터는 ASCII로 쓴다.
- **`.env`를 고쳐도 떠 있는 프로세스는 옛 값을 들고 있다.** 백엔드·Expo 둘 다 재시작해야 한다.
- **Google 설정이 먹었는지 확인하는 법** — 쓰레기 토큰으로 응답 코드를 가른다.
  ```bash
  curl -s -w "\nHTTP %{http_code}\n" -X POST http://localhost:8080/api/v1/auth/oauth/google \
    -H "Content-Type: application/json" -d '{"idToken":"not-a-real-token"}'
  ```
  **401**이면 정상, **500**이면 `GOOGLE_CLIENT_ID`가 주입되지 않은 것이다.
- **커밋을 나눌 때** — `git stash push --keep-index`로 각 커밋 상태를 격리해
  typecheck·lint를 돌리면 중간 커밋이 깨지지 않는다. 파일이 커밋 경계를 걸치면
  `git apply`로 훅만 골라 적용한다.
- 테스트 계정을 만들었으면 **DB와 브라우저 localStorage 양쪽을** 정리한다.
