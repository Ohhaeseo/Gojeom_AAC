## 3. 오답 노트 추가분 — ✅ AGENTS.md §4-1로 이관 완료

N-10~N-16 일곱 건을 옮겼다(N-10~N-12는 [08-17 문서](HANDOVER_2026-08-17.md)에서).
아래는 요약이고, **정본은 AGENTS.md §4-1이다.**

### N-13. 라이브러리가 웹에서 조용히 죽는다

`react-native-draggable-flatlist`를 넣었더니 **끌어도 아무 일이 없었다.** 셀 위치를
`findNodeHandle`로 재는데 **RN Web에 그 API가 없다.** 콘솔에 경고 한 줄만 남기고
에러도 던지지 않아, 화면만 보면 "왜 안 되지"에서 멈춘다.

**재발 방지** — 네이티브 라이브러리를 웹에 쓸 때는 **실제로 그 동작을 해 보고**
확인한다. 렌더링이 된다고 동작하는 것이 아니다. 지금은 `PanResponder`(코어)로
직접 만들었다(`DragList`). **끌기와 ▲▼ 버튼을 둘 다 준다** — 순서를 바꾸는 길이
최소 하나는 늘 열려 있어야 한다.

### N-14. 애너테이션과 선언 사이에 끼워 넣지 않는다

`RoutineRenameRequest`를 `RoutineSummary` 바로 위에 넣으면서
`@JsonInclude(ALWAYS)`를 떼어놨다. 애너테이션이 새 레코드에 붙어 **경로 A 응답에서
`category: null` 키가 사라졌다.** 기존 회귀 테스트가 잡아줬다.

### N-15. 마이그레이션을 쓰기 전에 기존 것을 전부 읽는다

V9에 `CREATE UNIQUE INDEX ux_consents_user_code`를 넣었는데 **V1이 이미 만들고
있었다.** V1의 앞부분만 보고 뒤쪽 인덱스 선언을 놓쳤다. `grep`으로 먼저 확인한다.

### N-16. 한글은 psql뿐 아니라 **curl에서도** 깨진다

N-5는 psql만 말하지만 **curl 본문의 한글 닉네임도 셸을 거치며 깨져** 400이 났다.
점검용 데이터는 ASCII로 쓰고, 한글이 꼭 필요하면 **UTF-8 파일로 만들어**
`psql -f`처럼 파일로 넘긴다.

## 4. 이번에 만든 것 — 요점만

### 만 14세 미만 차단 (`2aa376d`)

- **생년월일을 `users`에 뒀다.** `profiles.birth_date`는 프로필이 사진·우선순위까지
  받은 뒤에야 생겨서 늦다. 나이 확인은 **어떤 개인정보든 수집하기 전에** 끝나야
  한다. 같은 사실을 두 곳에 두지 않으려고 프로필 쪽은 없앴다(V9).
- 동의 4항목으로 분리. 얼굴 사진·건강 정보는 **민감정보**라 `BIOMETRIC`으로 따로.
- **거부한 항목도 행을 남긴다.** "물어봤는데 거부"와 "아직 안 물어봄"은 다르다.
- **Google 최초 로그인도 회원가입이다.** 값이 없으면 `CONSENT_REQUIRED`로 돌려보낸다.

| 민감정보 동의 누락 | 403 `CONSENT_REQUIRED` |

### 태스크 시점 분리 (`fcb3716`)

완료 체크가 태스크 단위라 "아침, 저녁"이 한 줄이면 아침만 한 상태를 표현할 수
없었다. **프롬프트와 코드 두 곳**에서 막는다(`TaskTimingSplitter`).

**잘못 자르는 쪽이 못 자르는 쪽보다 나쁘다.** "과일 먹기"를 "일 먹기"로 만드느니
한 줄로 두는 편이 낫다 — 단어 구분자(과·와·및)는 **앞뒤가 띄어져 있을 때만** 자르고,
5조각을 넘으면 나누지 않는다.

> 실측: 6개월 피부 목표에서 세안·보습이 아침/저녁으로 갈려 **taskCount 120**.

### 루틴 품질 · 인바디 · 식단 (`42a5690`)

**숫자를 사용자에게 그대로 읽어 주지 않는다** — "체지방 25kg이므로"처럼 쓰면
진단처럼 들린다(규칙 4). 그 사실이 반영된 태스크만 낸다.

## 7. 알아두면 시간 아끼는 것

- **한글을 셸로 파이프하지 않는다** (N-5 · N-16). psql도 curl도 마찬가지다.
  꼭 필요하면 UTF-8 파일로 만들어 `psql -f`로 넘긴다.
- **`.env`를 고쳐도 떠 있는 프로세스는 옛 값을 들고 있다.** 백엔드·Expo 둘 다 재시작.
- **마이그레이션을 추가했으면 백엔드를 재시작해야 적용된다.** 이번에 V10을 만들고
  재시작을 잊어 "칼럼이 없다"로 한 번 막혔다.
- **Google 설정 확인** — 쓰레기 토큰으로 응답 코드를 가른다. **401**이면 정상,
  **500**이면 `GOOGLE_CLIENT_ID` 미주입.
  ```bash
  curl -s -w "\nHTTP %{http_code}\n" -X POST http://localhost:8080/api/v1/auth/oauth/google \
    -H "Content-Type: application/json" -d '{"idToken":"not-a-real-token"}'
  ```
- **커밋을 나눌 때** — `git stash push --keep-index`로 각 커밋 상태를 격리해
  typecheck·lint를 돌리면 중간 커밋이 깨지지 않는다. 파일이 커밋 경계를 걸치면
  `git apply`로 훅만 골라 적용한다.
- **테스트 계정을 만들었으면 DB와 브라우저 localStorage 양쪽을** 정리한다.

## 8. 오후 갱신 — 확정된 답으로 만든 것

사용자에게 5·7번의 의도와 회의 안건 5번 답을 받아 이어서 작업했다.
**아직 커밋하지 않았다.**

### 8-1. 반복하는 루틴을 위로 (피드백 5번)

`lib/tasks.ts`가 **빈도 먼저, 그 다음 시점**으로 정렬한다.

빈도는 `timing` 문장에서 읽는다 — 프롬프트가 빈도가 섞일 때만 `"주 3회 저녁"`처럼
적게 되어 있어서(`RoutineGenerationPrompt`), **표기가 없으면 매일**이다.
`주 N회`끼리는 N이 큰 쪽이 위다.

```
기상 직후 물     (기상 직후)    ← 매일
점심 후 걷기     (점심 후)
자기 전 스트레칭  (자기 전)
주5회 저녁근력    (주 5회 저녁)  ← 주 N회는 아래로, N이 큰 쪽이 먼저
주3회 아침운동    (주 3회 아침)
```

### 8-2. 홈 다중 선택 (피드백 7번)

홈의 루틴 탭이 **토글**이 됐다. 고른 목표들의 태스크가 하나의 목록으로 합쳐지고,
목표별로 뭉치지 않고 **시점끼리 섞여** 나열된다. 줄마다 어느 목표의 일인지 붙는다
(하나만 골랐을 때는 붙지 않는다 — 되풀이할 이유가 없다).

**마지막 하나는 끌 수 없다.** 전부 꺼두면 빈 화면이 되고 사용자는 무엇을 잘못했는지
알 수 없다.

> 🔴 **여기서 한 번 걸릴 뻔했다** — `todayTasks`는 "오늘 회차" 하나를 날짜로 고른다.
> 목표를 여러 개 합친 뒤 전체에서 날짜 하나를 고르면, **시작일이 다른 목표는 그
> 날짜에 회차가 없어 통째로 사라진다.** 그래서 회차는 **목표마다 따로** 고르고
> 합친다. 그러려면 태스크가 자기 출처를 알아야 하는데 서버 응답에는 `routineId`가
> 없어서, `openRoutines`가 올릴 때 붙여 준다.

상태도 배열이 됐다 — `activeRoutineId` → `activeRoutineIds`.
**예전에 저장된 id 하나짜리 값도 읽는다**(`'['`로 시작하는지로 가른다). 안 그러면
쓰던 사람이 보던 목표를 잃는다.

### 8-3. 목표별 알림 시각 API (회의 안건 5번)

`notification_settings.default_time`은 사용자당 하나뿐이라 "아침 루틴은 7시,
자기 전 루틴은 22시"를 표현할 수 없었다.

| | |
| --- | --- |
| 마이그레이션 | **V12** — `routines.notify_time TIME` (nullable) |
| 엔드포인트 | `PATCH /routines/{id}/notification` |
| 응답 | `RoutineSummary`에 `notifyTime` 추가 (`"HH:mm"` · 없으면 `null` 키) |

- **NULL은 "정하지 않음"이고 기본 시각을 따른다.** 기본값을 목표에 복사해 두지
  않는다 — 복사하면 나중에 기본 시각을 바꿔도 이미 만든 목표는 옛 값에 묶인다.
- **켜고 끄는 것은 목표에 두지 않았다.** on/off는 사용자 단위다. 목표마다 두면
  "전체는 껐는데 목표는 켜져 있다"는 상태가 생긴다.
- `GET /routines/{id}`의 `notification.time`은 **실제로 적용되는 시각**이다.
  프론트가 둘 중 무엇이 이기는지 계산하지 않게 서버가 정해서 내려준다.
- **화면은 아직 없다.** API와 `setRoutineNotifyTime`까지만 있다.

### 8-4. 로그인 화면 Google 버튼

처음 쓰는 Google 계정이면 서버가 `CONSENT_REQUIRED`를 준다. 이제 빨간 오류 대신
**가입 화면으로 보낸다.**

- 분기는 **에러 코드**로 한다. 메시지 문자열로 가르면 문구를 다듬는 순간 조용히 깨진다.
  그래서 `ActionResult`에 `code`를 얹었다.
- **토큰은 들려 보내지 않는다** — 라우터 파라미터는 웹에서 주소창에 남는다.
  가입 화면에서 Google 버튼을 다시 누르면 그때 동의와 함께 넘어간다. 왜 이 화면에
  와 있는지 한 줄로 알려준다.

### 8-5. 홈 수치 대시보드 (회의 안건 2번)

`수분 82%` 같은 퍼센트 막대 4개를 걷어내고 **서버가 준 `categoryChanges`**로 바꿨다.

> **"채울 API가 없다"가 아니라 "만들면 안 되는 UI"였다.**
> [API.md](../API.md) §6.4가 `changeIntensity`를 텍스트로 정하며 **"퍼센트 게이지
> UI를 만들지 않는다"**고 적고 있고(v2 변경 ⑤가 이 필드를 숫자→텍스트로 바꿨다),
> 카테고리별 점수를 지어냈다면 PRD G-3과 `OutputValidator.SCORE`가 AI 출력에서
> 막는 것을 **화면이 대신 하는 꼴**이 된다.

`AppState.peekSavedResult`를 새로 뒀다. 새로고침으로 `result`가 비었을 때 최근
저장분을 **읽기만** 한다 — 기존 `openSavedResult`를 쓰면 `activeRoutineId`와
`tasks`가 초기화돼 **홈의 "오늘 할 일"이 같이 비어버린다.**

### 8-6. 덤으로 고친 것

`Routine.java`에서 `changeTitle`이 `syncStatus`의 Javadoc과 `syncStatus` 선언
**사이에** 들어가 있었다. N-14와 같은 모양이다. 순서를 바로잡았다.

### 8-7. 목표별 알림 시각을 고르는 화면

목표 카드에 넣었다. 펼친 카드가 **실제로 적용되는 시각**을 말하고,
목표가 자기 값을 갖고 있지 않으면 `기본 시각을 따르는 중`이라고 밝힌다 —
빈칸으로 두면 "알림이 없다"로 읽힌다.

- 편집 버튼은 카드 `Pressable` **밖**이다. 안에 넣으면 카드가 함께 눌린다. (N-11)
- 입력은 숫자만 들고 있다가 `07:30`으로 보여준다. 생년월일과 같은 방식이고
  (`lib/date.formatTimeInput`), **4자리를 채우기 전에는 오류를 띄우지 않는다.**
- **`기본 시각 따르기`를 확인 버튼과 따로 뒀다.** 입력을 지우고 저장하는 것으로
  대신하면 "빈칸 = 지움"을 사용자가 알아내야 한다.
- 켜고 끄는 것은 여기 없다. 화면 아래 `알림 설정` 토글 하나가 사용자 단위로 갖는다.

실측 — `25:60`에서 "시는 00~23 사이여야 해요", `07:30` 저장 후 카드가
`알림 07:30`, `기본 시각 따르기` 누르면 `21:00 · 기본 시각을 따르는 중`으로
돌아오고 **DB의 `notify_time`이 NULL**이 되는 것까지 확인했다.

### 8-8. Expo Push 알림

발송까지 붙였다. 등록 엔드포인트는 이미 있었고 **보내는 쪽이 없었다.**

| | |
| --- | --- |
| 마이그레이션 | **V13** — `notification_sends(routine_id, sent_on)` UNIQUE |
| 발송 | `RoutineNotificationSweeper` — 1분마다, 지난 **10분** 창 |
| 전송 | `ExpoPushClient` → `https://exp.host/--/api/v2/push/send` (키 불필요) |
| 프론트 | `expo-notifications` · 알림을 **켤 때** 권한을 묻고 토큰을 등록 |

**알림 문구에 목표 이름도 태스크 이름도 넣지 않는다.** 푸시는 잠금 화면에 뜬다.
목표 이름은 AI가 짓고 "모공 정돈과 생활 리듬을 함께 다듬기"처럼 나올 수 있어,
그대로 띄우면 **남이 볼 수 있는 자리에 피부·건강 상태가 드러난다.** 얼굴 사진과
건강 정보를 민감정보로 따로 동의받는 서비스가(PRD G-1) 알림으로 흘리면 안 된다.
문구는 `오늘의 루틴` / `고점으로 가는 오늘 할 일을 확인해보세요.` — 열어야 보인다.

**사용자당 한 번만 보낸다.** 목표 셋이 모두 기본 시각을 쓰면 21시에 똑같은 알림이
세 번 온다. 같은 시각에 걸린 목표는 묶어 하나로 보내고 기록은 목표마다 남긴다 —
아침 7시 목표와 자기 전 22시 목표는 여전히 따로 온다.

**기록을 먼저 남기고 보낸다.** 보낸 뒤에 남기면 그 사이에 스케줄러가 다시 돌아
같은 알림이 두 번 나간다. 중복은 코드가 아니라 **DB의 UNIQUE가** 막는다.

> 🔴 **여기서 한 번 물렸다 — `notify_time`은 DB에 UTC로 저장된다.**
> `hibernate.jdbc.time_zone: UTC`(application.yml) 때문에 API로 `07:30`을 넣으면
> DB에는 `22:30`이 앉는다. 읽을 때 되돌아오므로 화면은 멀쩡하다.
> **점검 데이터를 psql로 직접 넣었다가** 앱이 9시간 뒤로 읽어 스위퍼가 아무것도
> 집지 못했다. 알림 시각은 **반드시 API로 넣는다.** (§9)

프론트는 **알림을 켜는 순간** 권한을 묻는다. 앱을 열자마자 물으면 무엇에 쓰는지
모르는 상태에서 거절당하고, 거절한 권한은 기기 설정에서만 되돌릴 수 있다.
**등록에 실패해도 설정은 켜 둔다** — 웹에서 켜고 휴대폰에서 받는 것이 정상적인
흐름이라, 이 기기가 못 받는다고 설정을 되돌리면 켤 방법이 없어진다.
대신 왜 이 기기로는 안 오는지 문구로 알려준다(권한 거절 · 웹 · 개발 빌드 없음).

점심 후 걷기         건강 관리 목표 · 점심 후 · 10분
자기 전 보습하기      피부 관리 목표 · 자기 전

### Push 알림 실측

로컬 DB + 실제 Expo API로 확인했다. 가짜 토큰을 등록해 두고 스위퍼를 지켜봤다.

```
[스위퍼] today=2026-08-18 at=13:46:52 windowStart=13:36:52 due=2
쓰이지 않는 기기 토큰 1건을 지웠다
알림 발송 user=a85a2732 목표 2건 기기 1대
```

| 확인 | 결과 |
| --- | --- |
| V13 적용 | `now at version v13` |
| 같은 시각 목표 2건 | **푸시는 하나** (`목표 2건 기기 1대`) |
| 90분 뒤 목표 | 걸리지 않음 — `notification_sends`에 없다 |
| 다음 회차(60초 뒤) | `due=0` — **중복 발송 없음** |
| 죽은 토큰 | Expo가 `DeviceNotRegistered` → 토큰 삭제까지 실제로 탔다 |
| 단위 테스트 | 티켓 해석 4건 추가 (백엔드 **108건**) |

> 죽은 토큰 정리는 **실제 Expo 응답으로** 확인했다. 가짜 토큰이라 오히려 그 경로가
> 그대로 돌았다. 멀쩡한 토큰을 지우지 않는지는 단위 테스트가 지킨다 —
> **덜 지우는 쪽이 더 지우는 쪽보다 낫다.**

### 그래도 확인하지 못한 것

- **실제 기기에서 알림을 받는 것.** 발송까지는 확인했지만 받는 쪽은 개발 빌드가
  있어야 한다. `extra.eas.projectId`가 없어 지금은 토큰 자체가 발급되지 않는다
  (`registerForPush`가 `NO_PROJECT_ID`로 돌려준다). **`eas init` + 개발 빌드가 필요하다.**
- **AI를 부르는 경로.** 목표·분석 결과를 `psql -f`로 직접 심었다. `POST /routines`의
  실제 AI 생성(4~6초·과금)은 타지 않았다.
- **실제 Google 계정 로그인** · **끌어서 순서 바꾸기** · **실기기** — 그대로 남아 있다.
- **목표별 알림 시각을 고르는 화면.** API만 있고 UI가 없다.
