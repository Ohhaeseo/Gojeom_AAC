## 2. 🔴 APK를 굽기 전에 반드시 — `CHANGE-ME`

`eas.json`의 `preview`·`production` 프로필에 이렇게 적혀 있다.

```json
"EXPO_PUBLIC_API_BASE_URL": "https://CHANGE-ME.example.com/api/v1"
```

**가비아 도메인이 정해지면 이 값을 바꾸고 빌드해야 한다.** 그대로 구우면 앱이
존재하지 않는 주소를 물고 나오고, 로그인부터 아무것도 되지 않는다.

> **왜 `.env`가 아니라 `eas.json`에 있나** — `frontend/.env`는 gitignore 대상이라
> **EAS 빌드 서버로 올라가지 않는다.** 이걸 모르고 빌드하면 APK가 백엔드 주소도
> Google 클라이언트 ID도 모른 채 나오고, 모든 API 호출이
> `EXPO_PUBLIC_API_BASE_URL이 설정되지 않았습니다`로 죽는다.
> `EXPO_PUBLIC_*`은 **빌드 시점에 번들로 구워진다.** 값을 바꾸면 다시 빌드다.

### 프로필 3개 중 무엇을 쓰나

| 프로필 | 쓰나 | 이유 |
| --- | --- | --- |
| **`preview`** | ✅ | 진짜 APK + `internal distribution` → **EAS가 설치 URL을 준다.** 심사위원 배포는 이것 |
| `development` | 개발용 | `developmentClient`라 **PC에서 Metro가 돌아야** 화면이 뜬다. 남에게 주면 흰 화면이다 |
| `production` | ❌ | `app-bundle(.aab)`은 스토어 제출 포맷이라 **폰에 직접 설치가 안 된다** |

`development`의 주소는 `http://10.0.2.2:8080` — **안드로이드 에뮬레이터**가 PC의
localhost를 가리키는 주소다. 실기기로 붙이려면 공유기 IP로 바꿔야 하고, 평문 HTTP라
안드로이드가 막을 수 있다(`expo-build-properties`로 열어야 한다).

### 남은 순서

```
✅ SHA-1 만들기
✅ Google 콘솔 Android 클라이언트 등록
□  가비아 도메인 + HTTPS
□  eas.json의 CHANGE-ME → 실제 주소
□  eas build --profile preview --platform android
□  나온 URL로 직접 설치해 확인 → 그다음 심사위원에게
```

심사위원에게는 **"출처를 알 수 없는 앱" 경고가 뜨는 것이 정상**이고 `이 출처 허용`을
눌러야 설치된다고 미리 알려주는 편이 좋다.

## 3. 한 것

### 3-1. 안드로이드 Google 로그인 (`e389075`)

네이티브 버튼이 **스텁이었다** — 누르면 "앱은 준비 중이에요"만 떴다.
`@react-native-google-signin/google-signin`을 넣고 실제로 구현했다.

- 취소를 오류로 다루지 않는다. v13+는 예외가 아니라 `type: 'cancelled'`로 알린다.
- **원문 오류를 그대로 띄우지 않는다.** 영어인 데다 클라이언트 ID 같은 설정값이
  섞여 나올 수 있다. 사용자가 할 수 있는 일만 말한다.
- Expo Go로 열어 네이티브 모듈이 없는 경우도 문구로 갈랐다.
- 클라이언트 ID를 `services/googleClient.ts`로 옮겼다. `googleWeb.ts`가
  "웹에서만 불린다"고 적혀 있었는데 이제 네이티브도 같은 값을 쓴다.

### 3-2. 루틴 태스크가 동작 이름을 대게 (`5e0933a`)

`주 3회 근력운동`은 체크박스만 있고 무엇을 하라는 말이 없다. 두 가지를 막았다.

1. **`title`에 빈도·시점을 넣지 않는다** — 그건 `timing`이 이미 말한다.
   같은 말을 두 번 쓰면 15자를 빈도가 먹고 정작 무엇을 하는지가 사라진다.
2. **운동·동작을 묶어 부르지 않는다** — 맨몸 동작 하나를 고르고 `amountLabel`에
   횟수를 적는다.

실측 (체형 4주 · 4회, 태스크 17건):

| | 뭉뚱그림 |
| --- | --- |
| 이전 | **5건** — `저녁 근력운동` · `아침 스트레칭하기` |
| 지금 | **0건** — `스쿼트 하기 / 15회 2세트` · `플랭크 버티기 / 30초 3세트` |

### 3-3. 오버레이가 창 끝까지 늘어나던 것 (`5d1aad8`)

흐림·어둡게는 화면 전체를 덮는 게 맞지만 **그 안의 내용까지 전체 폭일 이유는 없다.**
`overlayColumn`을 새로 두어 `AppScreen.shell`과 같은 `maxWidth`에 모았다.
실기기(좁은 화면)에서는 원래 정상이었고 데스크톱 브라우저에서만 보이던 문제다.

### 3-4. 쓰지 않는 마이크 권한 (`32b36fa`)

`eas init`이 `android.permissions`에 **`RECORD_AUDIO`를 끼워 넣었다.**
`expo-image-picker` 플러그인의 기본값인데 **앱은 사진만 고른다**(`mediaTypes: ['images']`).

얼굴 사진과 건강 정보를 민감정보로 따로 동의받는 서비스가 쓰지도 않는 마이크 권한을
설치 화면에 띄울 이유가 없다. 플러그인에 `microphonePermission: false`를 줘서 막았다 —
**`app.json`에서 지우기만 하면 prebuild 때 다시 들어온다.**

### 3-5. Push 토큰이 풀렸다

`eas init`이 `extra.eas.projectId`를 써 넣으면서, `registerForPush`가
`NO_PROJECT_ID`로 돌아오던 원인이 사라졌다. **실기기 수신은 아직 확인하지 못했다.**

## 4. 🟡 답을 정해야 하는 것 — 루틴 일정 모델

**"1개월 루틴이면 하루마다 다른가?"에 대한 답: 같은 묶음이 매주 반복된다.**

`RoutineTxService.persistStandalone`이 이렇게 만든다.

```java
for (int week = 0; week < weeks; week++) {
    LocalDate scheduled = startDate.plusWeeks(week);   // 매주 같은 요일
    for (PlannedTask task : expanded) { save(...); }
}
```

4주 목표면 같은 태스크가 4번, 시작일과 같은 요일에 하나씩이다.
**경로 A(분석 기반)는 반복이 아예 없다** — 시작일에 한 번 놓이고 끝이며
`duration_weeks`가 NULL이다.

### 🔴 그래서 빈도가 일정과 어긋난다

**"주 3회"는 글자일 뿐 일정이 아니다.** 주 3회라고 써 놓고 그 주에 만들어지는 행은
**하나**이고 체크박스도 하나다. 3번 했는지 1번 했는지 구분할 방법이 없다.
**"매일"도 마찬가지다** — 4주에 체크박스가 4개다.

지금 체크박스의 뜻은 빈도와 무관하게 **"이번 주에 이거 했나"** 하나뿐이다.
코드 주석은 의도된 단순화라고 적고 있다 — *"매일 반복하면 4주에 168건이 되어 화면이
무너진다"*. 화면을 지키려다 의미를 잃은 자리다.

### 캘린더 제안 — 백엔드 변경은 0이다

*"루틴을 클릭하면 캘린더가 뜨고, 날짜를 누르면 그날 루틴이 보이게"* 는 데이터가
이미 다 있다.

| | |
| --- | --- |
| `routine_tasks.scheduled_date` | `DATE NOT NULL` — 태스크마다 날짜가 박혀 있다 |
| `routines.start_date` · `end_date` | 캘린더 범위 |
| `GET /routines/{id}` | `tasks[].scheduledDate`까지 **이미 전부 내려준다** |
| 진입점 | `routines.tsx`의 카드 `Pressable`이 이미 있다 |

**다만 지금 데이터로 그리면 한 달에 점이 4개 찍히고 나머지가 텅 빈다.**
경로 A로 만든 목표는 하루만 찍힌다. 캘린더는 이 문제를 고쳐주는 게 아니라 **드러낸다** —
지금은 "오늘 할 일"이 그날 걸린 회차만 보여줘서 빈 날이 안 보일 뿐이다.

> **순서가 있다. 1) 일정을 실제 빈도대로 펼치고 → 2) 캘린더를 붙인다.**
> `timing`의 "매일"·"주 3회"를 읽어 날짜로 펼치면 된다 — 프론트 `lib/tasks.ts`가
> 이미 그 문자열에서 빈도를 파싱하고 있어 규칙을 백엔드로 옮기면 된다.
> 마이그레이션은 필요 없고 행 수만 는다. 태스크 개수가 바뀌면 홈의 "오늘 할 일",
> 진행률 링, 알림 스위퍼가 함께 영향을 받는다.

**배포 전에 손대지 않기로 했다.** 반나절~하루짜리이고 영향 범위가 넓다.

## 4-2. 목표 캘린더 (`688f713`)

루틴 카드의 `캘린더` → 기간에 맞는 달력 → 날짜를 누르면 그날 할 일. 거기서 바로
완료 체크도 된다. **백엔드 변경 0** — `GET /routines/{id}`가 이미 태스크마다
`scheduledDate`를 준다.

🔴 **달력이 §4의 일정 문제를 드러낸다.** 4주 목표면 한 달에 배정일이 4일뿐이고
분석 기반 목표는 하루뿐이다. 빈 날에 "가장 가까운 날로 가기"를 붙여 막다른 길을
만들지 않았지만, **매일이 채워지려면 일정을 빈도대로 펼쳐야 한다.**

계산부는 `lib/calendar.ts`에 있고 단위 테스트 12건이 붙어 있다. 날짜는 처음부터
끝까지 `YYYY-MM-DD` 문자열로 다룬다 — `Date`로 바꿔 더하고 빼면 시간대에 따라
하루가 밀린다.

## 6. 알아두면 시간 아끼는 것

- **이 PC의 터미널은 Windows PowerShell 5.1이다. `&&`가 없다.** `;`로 잇거나 줄을
  나눈다. 이번 세션에서 `cd frontend && npx ...`로 한 번 물렸다.

- **`npx eas`가 아니라 `npx eas-cli@latest`다.** 패키지 이름이 `eas-cli`라
  `npx eas`는 `could not determine executable to run`으로 죽는다.

- **expo.dev 웹 로그인과 CLI 로그인은 별개다.** 웹에 로그인해도 `~/.expo/state.json`의
  `auth`는 비어 있다. `eas-cli login`을 따로 해야 한다.

- **Metro는 import를 넣기 전 중간 상태도 캐시한다.** 스타일을 먼저 고치고 import를
  나중에 넣었더니 `layout is not defined`가 재시작·`.expo` 삭제로도 안 없어졌다.
  캐시는 `%TEMP%\metro-cache`에 있다 — 거기까지 지워야 한다.

  ```powershell
  Remove-Item -Recurse -Force "$env:TEMP\metro-cache"
  ```

- **`eas init`은 묻지 않고 `app.json`을 고친다.** projectId·owner뿐 아니라
  플러그인이 요구하는 안드로이드 권한까지 써 넣는다. **실행 후 `git diff app.json`을
  반드시 본다.**

- **APK 배포는 `preview` 프로필이다.** `production`(app-bundle)은 폰에 설치되지 않고,
  `development`는 Metro 서버 없이는 흰 화면이다.
