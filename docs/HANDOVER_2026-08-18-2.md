## 2. 🔴 다음 사람이 가장 먼저 알아야 할 것

### `notify_time`은 DB에 **UTC로 저장된다**

`application.yml`의 `hibernate.jdbc.time_zone: UTC` 때문이다. API로 `07:30`을
넣으면 DB에는 `22:30`이 앉는다. 읽을 때 되돌아오므로 **화면은 멀쩡하다.**

점검 데이터를 psql로 직접 넣었다가 앱이 9시간 뒤로 읽어, 스케줄러가 아무것도
집지 못하는 것을 한참 헤맸다. **알림 시각은 반드시 API로 넣는다.**

### 프론트는 API 주소를 **빌드할 때 굽는다**

`EXPO_PUBLIC_API_BASE_URL`은 빌드 시점에 번들 안으로 들어간다. 실제로
`expo export` 결과물에 `localhost:8080`이 박혀 있는 것을 확인했다.

**서버에서 `.env`만 고쳐도 소용없다.** 주소가 정해진 뒤 다시 빌드해야 한다.

### 적용된 마이그레이션 파일을 고치지 않는다

V13에 주석을 덧붙였다가 Flyway 체크섬이 어긋나 기동이 막혔다.
이미 적용한 로컬 DB는 `flyway_schema_history`의 checksum을 갱신해야 산다.

## 3. 이번에 만든 것 — 요점

### 3-1. 목표별 알림 시각 화면 (`a58caca`)

목표 카드가 **실제로 적용되는 시각**을 말한다. 목표가 자기 값이 없으면
`기본 시각을 따르는 중`이라고 밝힌다 — 빈칸으로 두면 "알림이 없다"로 읽힌다.

- 편집 버튼은 카드 `Pressable` **밖**이다. 안에 넣으면 카드가 함께 눌린다. (N-11)
- `기본 시각 따르기`를 확인 버튼과 **따로** 뒀다. 입력을 지우고 저장하는 것으로
  대신하면 "빈칸 = 지움"을 사용자가 알아내야 한다.

### 3-2. Expo Push 알림 (`bd85283`)

등록 엔드포인트는 이미 있었고 **보내는 쪽이 통째로 없었다.**

| | |
| --- | --- |
| V13 | `notification_sends(routine_id, sent_on)` UNIQUE |
| 발송 | `RoutineNotificationSweeper` — 1분마다, 지난 **10분** 창 |
| 전송 | `ExpoPushClient` → `exp.host` (토큰이 곧 자격이라 키 불필요) |
| 프론트 | `expo-notifications` · 알림을 **켤 때** 권한을 묻는다 |

> **알림 문구에 목표 이름도 태스크 이름도 넣지 않는다.** 푸시는 잠금 화면에 뜬다.
> 목표 이름은 AI가 짓고 "모공 정돈과 생활 리듬을 함께 다듬기"처럼 나올 수 있어,
> 그대로 띄우면 남이 볼 수 있는 자리에 피부·건강 상태가 드러난다. (PRD G-1)

**사용자당 한 번만 보낸다.** 같은 시각 목표가 셋이면 알림은 하나다.
**기록을 먼저 남기고 보낸다** — 중복은 코드가 아니라 DB의 UNIQUE가 막는다.

### 3-3. 오늘 할 일 시점별 묶음 · 비교 슬라이더 (`21ab028` · `e043b3f`)

```
오늘 할 일 1/7
수시로              ← 시점 구분이 없는 것이 맨 위
아침 / 점심 / 저녁 / 자기 전
```

묶음 안에서는 자주 반복하는 것이 위다. `groupByTiming` 하나를 홈과 루틴 화면이
함께 쓴다 — 각자 나누면 두 화면의 순서가 갈린다.

`오늘 할 일 0/48`이 오늘 기준으로 바뀌었다. `tasks`에는 기간만큼 복제된 회차가
전부 들어 있어(6개월이면 24회차) 4개를 보여주며 48이라고 적고 있었다.

비교 이미지는 겹쳐 놓고 가운데 손잡이로 가른다. **끌기를 막던 것 넷**을 걷어냈다 —
사진 층의 `pointerEvents`, 자식 가로채기, `touchAction`, `userSelect`.
경계 위치는 state가 아니라 `Animated.Value`라 매 프레임 다시 그리지 않는다.
**사용자가 직접 확인해 "잘 된다"고 알려줬다.**

### 3-4. 화장품 8종 + AI 추천 (`18c6411` · `8194e03`)

- 데이터: `frontend/src/data/products.ts` · 사진 `frontend/assets/products/`
- 홈 맨 아래 **묶음별 진열**(진정·수분 / 장벽 / 정돈·결 / 자외선 / 액세서리)
- 분석을 마치면 그 위에 **결과 기반 추천**

**추천은 두 겹이다.**

1. **AI** — `GET /results/{id}/product-recommendation` (V14). 카탈로그를 주고
   id만 고르게 한다. 서버가 한 번 더 거른다(없는 id·용량 중복·3개 초과).
   **첫 호출만 AI(3초), 이후 캐시(0.1초).**
2. **규칙** — AI가 느리거나 실패하면 `recommendProducts`가 낱말로 고른다.
3. 둘 다 없으면 **성분 이야기**로 대신한다.

> **효능 수치를 화면에도 프롬프트에도 넣지 않았다.** 제조사 상세의 "진정 97.4%
> 개선" 같은 값을 우리 화면에 쓰면 **서비스가 그 효과를 보장하는 말**이 된다.
> PRD G-3이 금지하는 표현이고 우리가 검증한 수치도 아니다. 카탈로그에 수치가
> 섞이지 않는지 테스트로 막았다.

낱말은 한 번 다듬었다 — 한 글자짜리(`결`은 `결과`에도 걸린다), 지시하는 말
(`집중`은 안내 문장에 늘 있다)을 빼고, 개수가 아니라 **비율**로 잰다.

## 7. 알아두면 시간 아끼는 것

- **로컬 DB로 백엔드를 띄울 수 있다. Docker 필요 없다.** 이 PC에 PostgreSQL 18이
  서비스로 돌고 있다(`postgresql-x64-18`). (N-17)

  ```bash
  cd backend && set -a && . ./.env && set +a && SPRING_PROFILES_ACTIVE=local ./gradlew bootRun
  ```

  **`.env`는 Spring이 자동으로 읽지 않는다.** `set -a`로 주입해야 한다.

- **점검용 계정을 만들었으면 DB와 브라우저 `localStorage` 양쪽을 정리한다.**
  이 세션에서 쓴 계정은 전부 `%-check@example.com`이었고 모두 지웠다.

- **한글을 셸로 파이프하지 않는다** (N-5 · N-16). psql도 curl도 마찬가지다.
  UTF-8 파일로 만들어 `psql -f`로 넘긴다. 이번에도 `psql -c`에 한글을 넣어 한 번 물렸다.

- **JS `.click()`으로 RN Web 버튼을 눌러 점검하지 않는다.** 되는 것도 있고 안 되는
  것도 있어 "반응 없음"을 버그 근거로 쓸 수 없다. 실제 포인터로 확인한다.
  드래그는 합성 이벤트로 아예 판정할 수 없다.

- **API.md §5 엔드포인트 표가 뒤처져 있다.** 루틴 3종(이름 변경·순서 변경·알림
  시각)과 상품 추천이 표에 없다. §6 본문에는 다 있다.
