## 2. 🔴 Google 로그인 — 원인이 둘이었다

**이번 세션에서 가장 값진 기록이다.** 콘솔 설정도, 서버도, 클라이언트 ID도 처음부터
멀쩡했다. 막고 있던 것은 **요청 본문 한 필드**와 **검사 순서** 둘이었고, 둘 다
웹·안드로이드에 똑같이 걸렸다.

### 2-1. `toIsoBirthDate('')`가 `"--"`를 만들었다

빈 문자열을 잘라 붙이니 `"--"`가 나왔다. 가입 화면에서 생년월일을 비운 채 Google을
누르면 그 값이 그대로 서버로 갔고, Jackson이 `LocalDate`로 못 읽어
`HttpMessageNotReadableException` → **400**. 화면에는 아무 사유도 안 떴다.

8자리가 아니면 아예 만들지 않게 고쳤다. **반쯤 만든 값을 보내느니 아무것도 보내지
않는 편이 낫다** — 서버는 `birthDate`가 없으면 안내할 수 있지만, `"--"`는 요청
자체를 깨뜨려 그 길마저 막는다.

### 2-2. 🔴 나이를 동의보다 먼저 검사했다

이걸 고치고도 **로그인 화면**에서는 여전히 400이었다.

```java
// createGoogleUser (고치기 전)
ConsentPolicy.validateAge(request.birthDate(), ...);      // birthDate == null → 400
ConsentPolicy.validateConsents(request.agreedConsents()); // 여기까지 오지 못한다
```

로그인 화면에서 온 요청에는 생년월일도 동의도 없다 — **그것이 설계다.**
`GoogleLoginRequest` 주석과 API.md §6.1이 *"신규 계정인데 비어 있으면
`CONSENT_REQUIRED`로 돌려보내고 프론트가 가입 화면에서 받아 다시 부른다"*고 적어
두었다. 그런데 나이를 먼저 봐서 `VALIDATION_ERROR`(400)로 나가는 바람에, 프론트가
기다리던 `CONSENT_REQUIRED`(403)가 **영영 오지 않았다.** `login.tsx`의 가입 화면
안내가 죽은 코드였던 셈이다.

> **계약은 처음부터 맞았고 구현이 그 앞에서 막고 있었다.** 순서를 바꾸는 것으로
> 계약이 그대로 성립한다.

### 2-3. 어떻게 좁혔나 — 응답 코드가 지도였다

브라우저 콘솔에서 운영 서버를 직접 찔러 한 단계씩 지웠다. **이 방법을 다시 쓴다.**

| 보낸 것 | 응답 | 읽는 법 |
| --- | --- | --- |
| `{idToken:"fake"}` | 401 | 경로 공개 O · `GOOGLE_CLIENT_ID` 있음 · 검증기 도달 |
| `{… birthDate:"--"}` | **400** | 본문이 깨졌다 — 검증기까지 가지도 못한다 |
| `{… birthDate:"2000-01-31", 동의 3종}` | 401 | 형식 정상 · 가짜 토큰이라 거절된 것뿐 |

**500이 아니라 401이 나오는 것이 좋은 신호다.** 500이면 서버에 `GOOGLE_CLIENT_ID`가
없다는 뜻이다(`GoogleTokenVerifier`).

## 3. 실패 사유를 뭉개지 않는다 (`8645d75`)

**서버는 이미 정확히 말하고 있었는데 프론트가 버리고 있었다.** 서버는 무엇이 왜
틀렸는지를 `details`에 필드별로 담아 보내는데
(`GlobalExceptionHandler.handleValidation`), 프론트가 `message`만 읽어
**"입력값을 다시 확인해주세요."** 한 줄로 뭉갰다.

[lib/errors.ts](../frontend/src/lib/errors.ts)가 `details`를 살린다. **이 한 곳으로
로그인·가입·사진·분석·루틴이 함께 구체적으로 바뀐다.**

🔴 **한글이 든 값만 고른다.** `ANALYSIS_INVALID_STATE`처럼 `analysisId`(UUID)와
`status`(enum)를 사람이 읽을 문구와 함께 싣는 자리가 있어, 거르지 않으면 화면에
UUID가 뜬다.

🔴 **형식이 틀렸다고 버튼을 잠그지 않는다.** 잠가 두면 사용자는 왜 안 눌리는지 모른
채 화면을 노려보게 된다 — 안 되는 이유를 말하는 것이 그 화면의 일이다. 눌렀을 때
칸마다 사유를 붙이고 서버까지는 가지 않는다.

`ApiError`를 [services/apiError.ts](../frontend/src/services/apiError.ts)로 뺐다.
`services/api`는 세션 때문에 `AsyncStorage`(네이티브)를 끌고 오는데, 순수 함수가
그것까지 부르면 **테스트가 네이티브 없이 돌지 않는다.** 실제로 물려서 뺐다.

## 4. 나머지 고침에서 갈린 지점

### 4-1. 로고는 남은 높이만 가져간다

`overflow: hidden` 패널에 **고정 크기** 로고가 들어 있어 남은 높이가 모자라면 잘렸다.
실측 — 320dp에서 글꼴 1.3배면 위로 25px, 320×568에서 1.5배면 위아래 67px씩.

`flex: 1`로 로고가 남은 높이만 가져가고, `AnalysisPanel`은 그래도 넘칠 때
**잘리는 대신 스크롤**된다. 375×812에서는 지금까지와 똑같이 150px 그대로다.

### 4-2. 자르기 화면은 라이브러리 기본값이 스스로 어긋나 있었다

- 자르기 액티비티가 `Base.Theme.AppCompat` — 이름과 달리 **어두운** 테마다
- 툴바 색 기본값이 낮·밤 모두 `#00000000`(투명)이라 그 어두운 창이 비친다
- 아이콘 색은 기기 `uiMode`로 고르는데 앱이 라이트라 **검정**이 뽑힌다

→ 어두운 툴바에 검은 아이콘. 라이브러리가 색을 **이름으로** 찾으므로
(`ExpoCropImageUtils.applyPaletteToOptions`) 앱에서 같은 이름을 정의해 덮었다.
**낮과 밤에 같은 값을 넣는다** — 기기 설정에 따라 갈리면 같은 어긋남이 또 생긴다.

### 4-3. 진행 중 분석을 버릴 수 있게 했다

키워드를 고르다 화면을 벗어나면 분석이 `KEYWORDS_READY`로 남는데, 좀비 스위퍼는
이 상태를 **일부러 건드리지 않는다**(고르는 중일 수 있다). 그래서 그 행이 영영 남고
이후 모든 분석이 409로 막혔다 — **빠져나갈 길이 없었다.**

`DELETE /analyses/{id}`를 붙이고, 화면은 409를 만나면
**"이어서 하기 / 버리고 새로 시작"**을 묻는다. 이어하기는 남은 분석의 상태를 보고
키워드 화면이나 결과 화면으로 알아서 간다 — 이미 결과를 만들고 있는데 키워드를
다시 묻는 것은 틀린 화면이다.

### 4-4. 주 N회는 지난 날을 남긴다

`visibleTasks`가 **오늘과 앞으로 남은 날**에서만 덜어낸다. 지난 날은 기록이라 그대로
둔다(사용자가 정했다). **방금 체크한 줄도 남긴다** — 체크하는 순간 사라지면 되돌릴 수
없다. 캘린더는 **거른 뒤에** 날짜로 묶는다. 점은 있는데 눌러 보면 비어 있으면
사용자는 고장으로 읽는다.

### 4-5. 사진만 바꾸는 길

`POST /profiles`는 우선순위·키·체중·수면을 **모두** 요구해서, 사진 한 장 바꾸자고
신체 정보를 처음부터 다시 입력해야 했다. `PUT /profiles/me/photo`를 새로 두고
활성 프로필의 사진만 교체한다. **등록과 같은 얼굴 검증을 거치고**(건너뛰면 촬영
품질 게이트를 우회하는 뒷문이 된다), 이전 사진은 즉시 지우며, **사진이 바뀌었으니
프로필 요약도 다시 만든다**(요약이 사진을 보고 쓰인다).

### 🔴 물린 것 넷

**SSH만 막히고 웹은 멀쩡한 증상.** 보안그룹이 22번을 **내 공인 IP만** 허용한다
(DEPLOY_GABIA §3). 인터넷을 재접속하거나 망을 바꾸면 IP가 달라져
`Connection timed out`이 난다. 80·443은 전체 허용이라 앱은 멀쩡해 보인다.

```powershell
(Invoke-RestMethod https://api.ipify.org?format=json).ip   # 이 값을 보안그룹 22번에 /32 로
Test-NetConnection 1.201.117.65 -Port 22 -InformationLevel Quiet
```

**jar를 실행 중에 교체하면 종료 예외가 난다.** 옛 프로세스가 종료 훅에서
`NoClassDefFoundError`를 뱉는다(무해하지만 로그가 지저분하다).
**임시 경로에 올린 뒤 정지 → 교체 → 시작**하면 안 난다.

**PowerShell 5.1에는 `&&`가 없다.** `;` 또는 `if ($?) { }`를 쓴다.
Windows에서는 `./gradlew`가 아니라 `.\gradlew.bat`이다.

**웹 배포 절차가 문서에 없었다.** DEPLOY_GABIA §8은 *"프론트는 서버에 올리지 않는다
(APK다)"*로 멈춰 있어 도메인에 웹을 올린 뒤로 낡았다. 지금 절차는 이렇다.

```powershell
cd C:\AAC_gojeomAI\frontend; .\node_modules\.bin\expo export -p web
scp -r C:\AAC_gojeomAI\frontend\dist root@<IP>:/var/www/gojeom.new
ssh root@<IP> "rm -rf /var/www/gojeom.old; mv /var/www/gojeom /var/www/gojeom.old; mv /var/www/gojeom.new /var/www/gojeom"
```

> **백엔드를 먼저 올린다.** 새 프론트가 `DELETE /analyses/{id}`와
> `PUT /profiles/me/photo`를 부르므로, 웹이 먼저 가면 그 버튼들이 404로 죽는다.
> 지금은 백엔드(02:17)가 웹(01:58)보다 새것이라 안전한 방향이다.

## 6. 회원 데이터 전체 삭제

사용자 요청으로 운영 DB를 비웠다. **순서가 핵심이다.**

```
1) 백업     pg_dump → /opt/gojeom/gojeom-before-wipe.sql (634K · 권한 600)
2) S3 먼저  object key 50개를 storage_deletion_jobs 에 INSERT
             → StorageDeletionSweeper(60초)가 S3에서 삭제 → 큐 0 확인
3) DB 나중  DELETE FROM users;   (FK 8개가 전부 ON DELETE CASCADE)
```

🔴 **DB를 먼저 지우면 안 된다.** object key를 읽을 수 없게 되어 **얼굴 사진 19장이
버킷에 고아로 남는다.** 민감정보라 그것만은 피해야 한다.

지운 것 — 계정 9 · 프로필 19 · 분석 13 · 결과 13 · 참고사진 19 · 목표 5 · 서랍 5 ·
동의 36 · 구독 9, 그리고 **S3 객체 50개**(얼굴 19 · 참고 19 · 비교 12).

**복구는 사실상 불가능하다.** 백업으로 DB는 돌아오지만 S3 객체는 실제로 지워졌다.

### 지금 상태

- 모든 이메일·Google 계정으로 **처음 가입하는 것처럼** 동작한다
  (`ux_users_email_active`·`ux_users_provider` 둘 다 0건 · 하드 삭제라 흔적 없음)
- 버킷 `gojeom-media-kr-1234`(ap-northeast-2)는 그대로다 — 익명 요청에 403
  `AccessDenied`(버킷이 없으면 `NoSuchBucket`이 온다)
- 앱의 S3 접근도 살아 있다 — DeleteObject 50번이 전부 성공했다

## 7. 프론트 ↔ 백엔드 연동 점검

세션 마지막에 전수 대조했다.

| | 결과 |
| --- | --- |
| 프론트가 부르는 (경로 + 메서드) **39개** | **전부 백엔드에 존재** ✅ |
| API 호출 위치 | 전부 `services/backend.ts` 한 곳 (+ 토큰 갱신만 `api.ts`) ✅ |

| 분기 방식 | 문구가 아니라 **`code`로만** 분기한다 ✅ |

> 문구로 분기하는 곳이 없다는 점이 중요하다. `messageOf`가 이번에 서버 `message`
> 대신 `details` 문구를 돌려주게 바뀌었는데, 문구로 분기했다면 조용히 깨졌을 것이다.

## 8. 남은 것

### 🔴 FCM — 알림을 실제로 보내려면

백엔드 발송기도 프론트 토큰 등록도 **이미 다 되어 있다.** 막고 있는 것은 FCM 자격
하나다. 콘솔 작업 ~15분 + 재빌드 ~20분, 비용 0원.
절차는 [PUSH_FCM.md](PUSH_FCM.md)에 적어 두었다.

### APK 재빌드 — 세 가지가 한 빌드에 담긴다

자르기 테마 · FCM · 이번 프론트 수정 전부. **키스토어를 다시 만들지 않는다** —
SHA-1이 바뀌면 Google 로그인이 조용히 깨진다.

### 확인해야 할 것

- **Google 로그인 실제 성공** — 고치고 배포까지 했지만 진짜 계정으로는 못 눌러 봤다.
  처음 쓰는 계정이면 가입 화면으로 안내되고, 생년월일·동의를 채운 뒤 Google 버튼을
  **다시** 눌러야 계정이 만들어진다
- **안드로이드 SHA-1** — DEPLOY_GABIA §8-2에 *"기존 지문 `96:46:…:FE:20`이 등록돼
  있다"*고 적혀 있다. 재발급이 아니라 **현재 EAS 키스토어 지문과 같은지 확인**하면 된다
- **S3 업로드(PutObject)** — 삭제는 50번 성공했지만 업로드는 안 태워 봤다.
  첫 회원가입에서 사진을 올리는 순간 확인된다

## 9. 알아두면 시간 아끼는 것

- 🔴 **번들에서 한글을 grep 하면 헛돈다.** Expo 웹 export는 한글을 `\uXXXX`로
  이스케이프한다. "새 코드가 배포됐나"를 문자열로 확인하려다 **한 번 오판했다.**
  대신 **동작으로** 본다 — 예: 가입 버튼이 빈 폼에서 눌리는가(옛 빌드는
  `aria-disabled="true"`).

- **PowerShell 5.1의 `Get-Content`는 기본이 ANSI다.** UTF-8 파일을 읽으면 한글이
  깨진다. `[System.IO.File]::ReadAllText($p, [System.Text.Encoding]::UTF8)`을 쓴다.

- **Expo 플러그인은 `expo config --type introspect`로 검증한다.** prebuild 없이
  실제 병합 결과(AndroidManifest·colors.xml)를 볼 수 있다. `--platform` 플래그는
  이 버전에 없다.

- **`.easignore`가 있으면 EAS는 `.gitignore` 대신 그것을 본다.** 그래서
  `google-services.json`을 git에서는 빼고 빌드에는 올릴 수 있다. 이 저장소는 이미
  `.easignore`를 쓰고 있으니 **덮어쓰지 말고 필요한 줄만 더한다**(`/backend`,
  `/docs` 제외가 들어 있다 — 없애면 업로드가 무거워진다).

- **운영 오류는 응답 코드로 좁힌다.** 400은 본문이 깨진 것, 401은 인증/토큰,
  403은 정책(동의·권한), 409는 상태 충돌(프로필 없음·진행 중 분석).
  브라우저 콘솔에서 `fetch`로 직접 찔러 보면 몇 초 만에 갈린다.

- **콘솔 경고 대부분은 무해하다.** `COOP would block postMessage`(토큰은 도착한다) ·
  `useNativeDriver`(웹엔 네이티브 애니메이션이 없다) · `aria-hidden retained focus`
  (expo-router 컨테이너) · `A listener indicated an asynchronous response`
  (**브라우저 확장 프로그램**이다). 진짜 오류는 네트워크 4xx/5xx 줄이다.
