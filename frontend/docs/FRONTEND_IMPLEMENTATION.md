# GO. 프론트엔드 최종 구현 명세

> 상태: 구현 기준 확정본  
> 대상: iOS 아이폰 우선 Expo React Native 앱  
> 작업 루트: 저장소의 `frontend` 디렉터리  
> 작성 기준: 사용자 대화 요구사항, Figma 화면 레이어 41개, API v2.0/v2.1, 사용자 제공 에셋

## 1. 문서 목적과 우선순위

이 문서는 GO. 앱의 프론트엔드를 구현할 때 사용하는 최종 실행 명세다. 화면을 구현하거나 수정하기 전에 이 문서와 최신 API 명세를 함께 확인한다.

서로 충돌하는 정보가 있으면 다음 순서로 판단한다.

1. 사용자가 대화에서 명시적으로 확정한 최신 결정
2. 이 문서의 확정 요구사항
3. 최신 `API.md`의 데이터 계약과 상태 규칙
4. `C:\Users\nan04\Desktop\레이어모음`의 화면 PNG 41개
5. 프로젝트의 `AGENTS.md`
6. 오래된 `PROJECT_BRIEF.md`, `docs/API_SPEC.md`, `docs/IMPLEMENTATION.md`

`docs/API_SPEC.md`는 초기 초안이므로 최신 `API.md`와 충돌하면 사용하지 않는다.

### 확정된 예외

- 홈의 피부 상태 대시보드는 최신 API에 필드가 없어도 유지한다.
- 피부 대시보드는 외모 점수나 등급이 아니라 수분·유분·각질·톤의 참고 상태 지표로 표현한다.
- 실제 API가 생기기 전까지 프론트 mock 데이터로만 표시한다.
- `23 목표` 화면의 하단 활성 탭은 레이어 이미지와 달리 `프로필`이 아니라 `루틴`이다.

## 2. 제품과 구현 범위

GO.는 사용자의 현재 정보와 원하는 분위기를 바탕으로 실행 가능한 관리 방향과 루틴을 제공하는 모바일 프론트엔드 앱이다.

### 이번 프론트엔드 범위

- Expo React Native + TypeScript + Expo Router
- iOS 아이폰 우선 디자인 및 검수
- 로그인·회원가입 UI와 로컬 mock 동작
- 프로필 등록 전체 흐름
- 고점 분석 전체 흐름
- 결과 저장, 서랍, 목표·루틴, 프로필, 설정
- API 명세와 동일한 TypeScript 타입과 mock 응답
- 로딩·완료·빈 상태·오류·재시도 UI
- 카메라/갤러리 선택, 미리보기, 권한 상태

### 이번 범위에서 제외

- 백엔드 서버 구현
- 데이터베이스와 실제 데이터 저장
- OpenAI 또는 다른 AI 공급자 직접 호출
- 실제 Google·Naver·전화 OAuth 연결
- 결제 서버와 푸시 전송 서버
- 프론트 코드에 비밀키 저장

소셜 로그인은 로고·버튼·눌림 효과까지만 구현한다. 백엔드 준비 후 이벤트 핸들러만 교체할 수 있게 분리한다.

## 4. iOS 우선 원칙

- 아이폰 Safe Area의 상단 노치·Dynamic Island와 하단 홈 인디케이터를 침범하지 않는다.
- `SafeAreaView` 또는 `react-native-safe-area-context`의 inset을 사용한다.
- 키보드 표시 시 입력 필드와 CTA가 가려지지 않도록 KeyboardAvoidingView와 자동 스크롤을 적용한다.
- iOS 사진 접근 권한, 카메라 권한, 설정 앱 이동을 구현한다.
- 스크롤은 iOS 관성 스크롤을 유지하며 상단 고정 헤더와 하단 네비게이션은 흔들리지 않게 분리한다.
- 디자인 검수 기준은 iPhone이며 Android는 레이아웃이 깨지지 않는 수준으로 대응한다.
- Figma 458px 수치를 기기 폭에 맞게 비율 환산하되 터치 영역은 최소 44pt로 보장한다.

- 시작 스플래시 첫 상태와 일반 상단 워드마크에 사용

- 네비게이션 중앙과 분석 중에는 얼굴 로고를 연한 민트색 원형 컨테이너 안에 넣는다.

## 7. 모션 원칙

### 공통

- 일반 상태 전환: 150~250ms `ease-out`
- 버튼 눌림: scale `1 → 0.98 → 1`
- 콘텐츠 등장: opacity와 4~8pt의 짧은 translateY 조합
- 과도한 바운스·반짝임·연속 진동은 사용하지 않는다.
- iOS의 Reduce Motion이 켜지면 회전·큰 이동을 제거하고 페이드 중심으로 축소한다.

### 실행 로고 전환

- 로고 1과 로고 2는 서로 다른 공식 에셋이다.
- 글자와 점을 코드에서 임의로 다시 그려 모핑하지 않는다.
- 로고 1을 약하게 축소·페이드아웃하고 동일 중심의 로고 2를 페이드인·정착시킨다.
- 전체 전환 권장 시간: 800~1000ms
- 마지막에는 로고 2가 흐릿하지 않은 원본 크기로 정착한다.

### 분석 중 팽이 회전

- 대상: 프로필 분석, 고점 분석, 목표 설계 중
- 로고가 화면을 굴러다니지 않는다.
- 원형 얼굴이 세워진 채 제자리에서 팽이처럼 도는 느낌을 준다.
- `rotateY`와 가벼운 scaleX 변화를 조합해 세로축 회전감을 만들 수 있다.
- 반복 주기 권장: 약 1000~1200ms
- 수평·수직 위치 이동은 하지 않는다.

### 분석 완료 전환

1. 반복 회전 속도를 감속한다.
2. 정면 방향에 가까운 위치에서 멈춘다.
3. 기본 얼굴을 150~220ms 동안 페이드아웃한다.
4. 윙크 얼굴을 같은 위치·같은 크기로 페이드인한다.
5. 완료 문구와 CTA를 아래에서 짧게 올린다.

이미지를 한 프레임에서 갑자기 교체하지 않는다.

### 스위치

- thumb 위치, track 색상, 그림자를 약 180~220ms에 함께 전환한다.
- iOS 스위치의 물리감을 따르되 Figma의 크기·민트색을 유지한다.
- off/on 모두 접근성 role과 value를 제공한다.

## 8. 공통 레이아웃

## 10. 화면별 구현 명세

### 00 정보 삭제 안내 2종

- 제목: `삭제하시겠어요?`
- 설명: `삭제한 내용은 복구할 수 없어요.`
- 종류에 따라 보조 문구를 분기한다.
  - 계정·목표 정보는 삭제되지 않음
  - 해당 AI 분석 및 추천 내용만 삭제됨
- `되돌아 가기`가 상단 primary다.
- `삭제하기`는 하단 danger outline이다.
- 뒤 화면은 사용자 요청대로 약한 블러를 적용한다.

### 00 화면 이탈 안내

- 제목: `이동하시겠어요?`
- 작성 내용은 임시 저장된다는 안내를 표시한다.
- `계속 작성하기`를 primary로 둔다.
- `이동하기`는 중립 secondary다.
- 이동 시에도 작성 상태를 보존할 수 있는 store를 사용한다.

### 01 실행

- 첫 상태: 공식 로고 1 `GO.`
- 두 번째 상태: 공식 로고 2 얼굴형 로고
- 두 에셋을 자연스럽게 크로스페이드한다.
- 얼굴 로고에 원형 배경을 추가하지 않는다.
- 완료 후 02 로그인 선택 화면으로 이동한다.

### 02 로그인 선택

- 얼굴형 GO. 로고, 소개 문구, 개인정보 안내를 표시한다.
- `기존 회원 로그인`은 진한 네이비 버튼이다.
- `처음 시작 회원가입`은 민트 버튼이다.
- CTA는 눌림 효과와 disabled 중복 탭 방지를 적용한다.

### 03 로그인 / 03-1 회원가입

- 고정 상단 뒤로가기와 화면 제목
- 아이디/이메일, 비밀번호, 비밀번호 확인 입력
- 키보드 타입, secureTextEntry, 오류 메시지, 제출 중 상태 구현
- 소셜 로그인 로고는 UI만 제공한다.
- API v2 기준 실제 지원 계약은 LOCAL과 GOOGLE이며 다른 로고는 프론트 placeholder다.

### 04 이름 설정

- 환영 상태 → 예시 비교 이미지 안내 → 이름 입력 영역으로 이어진다.

## 11. API v2 핵심 계약

### 공통

- Base: `/api/v1`
- JSON: camelCase
- 성공: `{ success: true, data }`
- 실패: `{ success: false, error: { code, message, details } }`
- `error.message`를 사용자에게 그대로 보여준다.
- UTC 날짜는 프론트에서 KST로 변환한다.

### 인증

- Access Token 30분, Refresh Token 14일
- 401 `AUTH_TOKEN_EXPIRED` 시 refresh 후 원 요청 1회 재시도
- refresh 실패 시 직전 경로를 보존하고 로그인으로 이동

### 카테고리

- 프로필 우선순위와 루틴: `SKIN | BODY | HEALTH`
- 키워드만: `SKIN | FACE | BODY | HEALTH`
- 두 enum을 합치지 않는다.

### 업로드

- 프론트 검증 → presigned 발급 → storage 직접 PUT → objectKey 전달
- 서버에 multipart를 보내지 않는다.
- 조회 URL은 10분 만료이므로 영구 저장하거나 캐시하지 않는다.

### 분석 폴링

- `GET /analyses/{id}` 단일 폴링
- 서버 `pollAfterMs` 존중
- 최대 60초
- `KEYWORDS_READY`에서도 폴링 유지
- DONE 뒤 imageStatus PENDING이면 결과를 먼저 그리고 이미지 폴링 지속

### 결과

- disclaimer 항상 노출
- categoryChanges 항상 세 건
- changeIntensity는 텍스트 배열
- 퍼센트 변화 강도 UI를 만들지 않는다.
- 결과 자동 저장 금지

### 목표 생성

- `FROM_ANALYSIS`: 저장 결과를 사용해 목표 1개 생성
- `STANDALONE`: 1~3개 category와 1~12주 기간으로 생성
- 저장 결과가 없으면 분석 기반 경로를 disabled하고 직접 생성으로 유도한다.
- 응답의 `routines`는 항상 배열이다.

## 12. mock 전략

- API 함수와 화면에서 mock 데이터를 직접 분기하지 않는다.
- 동일한 service interface 아래 `mockAdapter`와 향후 `httpAdapter`를 둔다.
- mock 응답도 API 필드, enum, null 가능성을 그대로 따른다.
- 피부 상태 대시보드만 명세 외 프론트 전용 데이터로 별도 타입을 둔다.
- 분석 폴링은 시간에 따라 EXTRACTING → KEYWORDS_READY → GENERATING → DONE으로 진행되게 한다.
- 실패 데모를 위해 timeout, no credit, image failed, network error fixture를 둔다.

## 13. 필수 오류·빈 상태

- 카메라 권한 거부
- 사진 접근 권한 거부
- 파일 10MB 초과
- 얼굴 미검출
- 여러 얼굴
- 저화질
- 인바디 OCR 실패
- 프로필 미완성
- 분석권 없음
- 콘텐츠 정책 차단
- 분석 60초 초과
- 네트워크 오류와 재시도
- 비교 이미지 SKIPPED/PENDING/FAILED
- 서랍 결과 없음
- 목표 없음

- 알림 권한 없음

## 14. 개인정보와 표현 원칙

- 외모를 점수·등급·상위 퍼센트로 평가하지 않는다.
- 참고 사진 인물의 얼굴 복제를 표현하거나 약속하지 않는다.
- 의료 진단, 시술 권유, 효능 보장을 하지 않는다.
- 결점 중심 문구보다 실행 가능한 긍정 표현을 사용한다.
- 사용자가 입력하지 않은 정보는 분석 근거로 표현하지 않는다.
- 원본 사진은 분석 목적 외 공개되지 않는다는 안내를 유지한다.
- 면책 문구는 결과에서 숨기거나 접을 수 없다.

2. 공식 로고와 개별 SVG/PNG 에셋 정리
3. 공통 버튼·입력·체크박스·스위치·카드·모달
4. Safe Area 기반 Screen, StickyHeader, BottomNavigation
5. 실행·로그인·회원가입·이름 설정
6. 프로필 등록 05~10
7. 홈·프로필·설정
8. 고점 등록·분석·키워드·결과 12~18
9. 서랍 19

12. 오류·빈 상태·Reduce Motion
13. TypeScript, lint, Expo export 검사
14. iPhone Expo Go 실제 기기 검수

## 18. 완료 기준

- 00~23 주요 화면이 하나의 앱 흐름으로 연결된다.
- 앱을 재실행해도 데모에 필요한 mock 상태가 예측 가능하다.
- 우선순위 선택 순서와 삭제 재정렬이 자연스럽다.
- 두 공식 로고가 올바른 위치에서 사용된다.
- 분석 중 팽이 회전과 완료 윙크 전환이 끊기지 않는다.
- 21/22는 20 위 overlay로 동작한다.
- 모든 삭제·이탈 모달 뒤에 약한 블러가 적용된다.
- 스크롤 화면의 헤더와 하단 네비게이션이 고정된다.
- 탭별 활성 상태가 정확하며 23은 루틴 활성이다.
- 피부 상태 대시보드가 mock으로 유지된다.
- API v2 타입과 화면 상태가 일치한다.
- 소셜 로그인은 프론트 UI만 존재한다.
- iPhone Safe Area, 키보드, 홈 인디케이터에 가려지는 요소가 없다.
- `npm run typecheck`, `npm run lint`가 통과한다.
- 실제 비밀키가 프로젝트에 없다.

## 19. 구현 전 남은 에셋·디자인 확인 목록

다음 항목은 없어도 코드 구현은 가능하지만 원본과 완전히 동일한 품질을 위해 있으면 좋다.

- 공식 로고 1 `GO.` 워드마크 원본 SVG 또는 투명 PNG
- 설정, 연필, chevron 등 개별 아이콘 원본
- 스위치 OFF 원본 상태
- 입력창 focus/error 상태
- 사진 권한 거부·분석 실패의 확정 시안
- 비교 이미지 SKIPPED/PENDING/FAILED 시안
- API v2의 목표 생성 두 경로 선택 화면

새 에셋을 받으면 `assets`에 의미 있는 영문 파일명으로 저장하고 이 문서의 목록을 갱신한다.
