# GO. 프론트엔드 작업 지침

이 프로젝트는 GO. (고점)의 모바일 프론트엔드 MVP다. 모든 작업은 저장소의 `frontend` 디렉터리에서 수행한다.

## 기술 기준

- Expo React Native + TypeScript + Expo Router를 사용한다.
- 화면은 최신 Figma 시안과 사용자가 제공한 원본 에셋을 최우선으로 구현한다.
- 상태·레이아웃이 반복되는 UI는 공통 토큰과 컴포넌트로 분리한다.
- API 연동 전에는 API 명세와 동일한 TypeScript 타입 및 mock 데이터로 전체 흐름을 완성한다.

## 디자인 및 에셋

- 색상, 간격, 타이포그래피, 버튼, 입력창, 체크박스, 스위치, 모달, 하단 네비게이션은 재사용 가능한 컴포넌트로 만든다.
- `assets`의 사용자 제공 로고·아이콘·참고 이미지를 우선 사용한다. 이미지 한 장에 여러 상태가 섞여 있으면 원본을 보존한 채 상태별 파일로 분리한다.
- 하단 네비게이션은 탭별 활성 상태가 자연스럽게 전환되어야 하며, 가운데 GO. 버튼의 네온·그림자 효과를 유지한다.
- 스크롤 화면의 뒤로가기 + GO. 헤더는 상단에 고정하고, 스크롤 시 반투명 블러·구분선 상태로 전환한다.
- 모든 이탈·삭제 확인 모달은 약한 배경 블러를 적용한다.

## 인터랙션 및 접근성

- 기본 전환은 150~250ms `ease-out`을 사용한다. 버튼 탭은 과하지 않은 축소 피드백을 둔다.
- 우선순위는 `SKIN`, `BODY`, `HEALTH`의 배열 순서가 1~3순위다. 선택·삭제·재정렬은 자연스럽게 애니메이션한다.
- 분석/목표 설계 로딩은 GO. 얼굴 로고가 팽이처럼 제자리 회전하고, 완료 시 감속하며 윙크 로고로 전환한다.
- 스위치·체크박스·활성 탭은 상태 변경이 즉시 튀지 않도록 색상·위치·투명도를 애니메이션한다.
- 터치 대상은 최소 44pt를 확보하고, `reduce motion` 환경에서는 복잡한 모션을 페이드 전환으로 줄인다.

## API 계약과 데이터 처리

- 최신 `API.md`가 프론트와 백엔드의 계약이다. 요청·응답은 `camelCase` 타입으로 정의하고 임의 필드를 추가하지 않는다.
- API Base URL 등 공개 환경 변수만 `EXPO_PUBLIC_*`에 둔다. 비밀키·OpenAI 키·PG 키는 프론트에 넣지 않는다.
- 인증은 Access Token 만료 시 refresh 후 원 요청을 1회 재시도하고, 실패하면 직전 경로를 보존한 채 로그인으로 이동한다.
- 이미지는 MediaPipe 검증 후 presigned URL에 직접 PUT한다. 서버 multipart 업로드와 이미지 URL 영구 캐싱을 하지 않는다.
- 분석 폴링은 최대 60초이며 `KEYWORDS_READY`에서도 계속한다. 결과의 `comparisonImage.status` 4가지 상태를 모두 처리한다.
- `disclaimer`는 결과 화면에 항상 노출한다. 외모 점수·등급·순위 UI, 의료 진단·시술 권유 UI는 구현하지 않는다.

## 프론트 범위

- 소셜 로그인은 UI와 로고만 구현하며 실제 OAuth 연동은 백엔드 준비 후 연결한다.
- 백엔드 API, 데이터베이스, AI 호출, 결제·푸시 서버 구현은 현재 범위 밖이다.
- 인바디 OCR 결과는 폼에 채우기만 하고, 사용자가 확인·수정한 뒤 프로필 저장 요청을 보낸다.

- 작업 완료 시 변경 파일, 실행 방법, 남은 API 의존성 및 가정을 간단히 보고한다.
